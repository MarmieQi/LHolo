# 投影分区可见性与外壳优化

## 实现边界

- 保留异步文件加载与现有单线程网格执行器。文件任务统一由 `structure/StructureFileLoader` 管理，普通加载和恢复共用单任务入口；不在每帧等待任务，世界销毁及模组卸载时才等待已有任务。
- `core/ProjectionFrustum.h` 只做矩阵数学，`core/ProjectionVisibilityRules.h` 管理包围盒与调度规则，`runtime/ProjectionVisibility.cpp` 适配游戏相机。游戏对象不进入纯规则测试。
- 实际依赖为 LeviLamina 26.60.0。相机矩阵来自该包 `mc/deps/renderer/Camera.h` 的 `viewMatrixStack`、`projectionMatrixStack` 和内联 `getProjectionMatrix()`。投影绘制、可见性、透明排序及创建选区边框共用 `render/RenderCamera.h`，通过 `BaseActorRenderContext::Impl::mCameraTargetPosition` 读取原有相机相对渲染原点；不使用 `mImpl` 的固定字节偏移或 float 下标。26.60 前置捕获成员的存储尺寸变化，不得继续沿用旧布局。
- 方块实体提交的空 `MaterialPtr` 从当前渲染上下文中的有效句柄复制，再清空副本的共享引用，继续表示不强制覆盖原版材质。默认构造未导出时，也不得将全零字节数组强转为含 `shared_ptr` 的对象；副本仅在当前提交作用域内存活，不修改游戏句柄或跨帧保存材质。
- 只提取四个视锥侧面，不推断近远平面、反向 Z 或深度范围；矩阵、包围盒无效时保留绘制。版本适配后仍需实机回归移动靠近、第三人称、远坐标、分层和边框位置。
- 本轮遮挡优化是邻接内部几何剔除，不读取 GPU 深度，不提供 HZB 或视点相关的整栋建筑遮挡判断。

## 数据流与算法

1. 布局重建时，用现有结构变换函数转换分区八个角落的方块原点，再加入单位方块范围，得到构建包围盒。包含负坐标、非整分区尺寸、旋转和镜像。
2. 构建结束时，汇总实际 CPU 网格顶点范围，涵盖模型、液体、占位模型和纠错网格。通过 generation/revision 检验后，包围盒随网格一起发布；不使用原始分区范围裁剪越界模型。
3. 每个不透明阶段在纠错更新、网格接收之后计算可见性，绘制各桶复用结果。同步回退构建新网格后补算可见性。方块实体继续沿用原版渲染距离检查，避免用方块大小裁剪光柱等特殊渲染。
4. 单次线性扫描选择分区：可见增量、可见首次、周边预加载、后台分区，同级按距离排序。预加载范围将包围盒向外扩展 16 格。每第八次成功派发使用轮转选择，防止后台任务饥饿；未成功提交不消耗该次序号。
5. 不透明整方块被六个不透明整方块包围时跳过原版细分。玻璃、部分形状和缺失邻居不作为完整遮挡物。
6. 纠错单元只计算一次六邻面掩码，填充和线框复用；完全内部单元不进入网格生成。保留错误类型、错误状态、多余和缺失的优先级，保留外表面的逐格线框，不改变材料与放置数据。

视锥分类和任务选择均为 O(分区数)，不进行逐帧逐方块可见性检测。纠错表面邻居查询从填充、线框各六次，变为共享六次；生成量仍取决于结构形状。视野外分区后台补齐，因此当前版本不限制最终全结构显存驻留。

## 验证与游戏内对比

- 运行 `xmake -y` 和 `xmake -y LHoloLogicTests`，再运行 `build/windows/x64/release/LHoloLogicTests.exe`。
- 纯规则测试覆盖无效矩阵、透视侧面、视锥相交、12 种旋转镜像组合、负分区坐标、调度优先级和轮转公平性。
- 密实体素测试跨越 16³ 分区边界；32³ 实心体仅有 6×32² 个外表面，切到单层时重新暴露上下表面。
- 游戏内以相同文件、相机位置、画质对比：首次出现、转头补齐、切层、移动、旋转、镜像、液体、箱子、告示牌和穿透纠错。检查非对称结构与视锥边缘，不能只看完整立方体。
- 沿用每 64 个成功上传分区的 debug 汇总，增加可见分区数量与 revision 过期任务数量。可见数量是最近一次分类结果，未取得 CPU 顶点的分区保守计为可见。结合快照、构建、上传平均/峰值，分辨渲染筛选收益与初始化停顿。
- 没有游戏内采样时，不把算法查询次数减少或测试通过表述为实际帧率提升。整结构初始化、注册表解析和异步文件任务管理是独立后续任务。

## 快速转头与移动：CPU 绘制列表缓存

- `core/ProjectionDrawCache.h` 只缓存分区编号、局部中心、桶掩码与 CPU 数组，不保存网格、材质、世界、维度、玩家指针，也不保存调用方回调。
- `mesh/ProjectionDrawLists.cpp` 在网格/布局版本变化时收集资源存在性。渲染仍即时检查 `isValid()`，避免把 GPU 缓冲区尚未就绪当作永久缺失。
- 视锥矩阵、相对原点、激活代次、网格版本和分区数量完全相同时复用分类；这些键变化时重新分类，不延迟相机转头的可见性更新。
- 两个渲染阶段共享准备好的列表。实心/裁剪桶只在不透明阶段提交，半透明地形、液体、占位和纠错仅在各自原有阶段提交。减少重复全分区扫描、临时数组分配和当前阶段用不到的排序。
- 原地转头复用不依赖方向的距离顺序，只筛选当前可见项；持续移动时改为只排序可见候选，避免窄视野仍排序整张蓝图。距离每分区计算一次，比较器不再反复读取世界坐标。停下后首个新视图可重新建立全局顺序。
- 在资源收集阶段按所有驻留项预留数组容量，逐批发布资源时按几何增长扩容，避免每新增一个分区就重新分配；转头切换可见集不会触发列表扩容。排序只修改缓存编号，不修改 GPU 网格。
- 已移除只统计有效网格数量、没有消费结果的 preflight 全扫描，避免加载时每次接收网格都重复扫描全结构。

### 失效与释放

- 接收通过版本校验的网格、同步回退构建、旋转/镜像清除网格、布局中心变化时递增绘制版本；新增纠错分区还通过数量键失效。
- 移动投影或相机改变局部相机位置，按已有缓存规则更新距离顺序与列表；不再存在整体透明度模式切换。切层通过布局和网格发布版本失效。
- 缓存属于 `ProjectionState`，在 `ProjectionSession::withLockedState` 的锁内访问。工作线程不访问活动绘制缓存；网格结果通过原有 generation/revision 验证后发布。
- 切维度、退出世界、关闭投影仍沿用先停止并等待网格工作线程、再释放会话状态的顺序。缓存随状态销毁，编号不会解引用已释放资源；新的 activation 也会强制重建缓存。
- CPU 绘制缓存与网格任务仍按原有生命周期释放。文件任务独立拥有 future，关闭投影/退出世界通过 StructureSession 的请求版本拒绝迟到结果；恢复结果也必须校验版本，不能绕过清理重新激活。菜单路径只在 UI 回调内写入。
- `.mcstructure` 的原版 `StructureTemplate` 依赖世界持有的 unknown-block registry。实际 26.60.0 API 返回 `optional_ref<Level>` 和 `NonOwnerPointer<IUnknownBlockTypeRegistry>`，均不能延长世界寿命。因此文件任务启动前独立注册 `LevelListener`，即使尚无活动投影也在 `onLevelDestruction` 中先清除发布意图，再等待解析完成；回调后丢弃 Level 指针，不对销毁中的 Level 调用 removeListener。不在普通关闭投影或每帧路径等待解析；退出世界时若仍在解析大文件，会等待有限的剩余工作。

### 复现与测量

- 常规逻辑测试新增与无缓存参考实现的逐项结果对比，覆盖快速转头、连续移动、窄视野、透明模式切换、资源替换/清空、分区增减、新激活和会话销毁，并验证两个阶段不重复排序、转头不扩容。
- 运行 `build/windows/x64/release/LHoloLogicTests.exe --benchmark-draw-cache` 比较重建参考算法和缓存算法：16384 个分区、240 次视图更新，分别测试原地转头、连续移动及窄视野移动。该基准只测 CPU 列表准备，不运行游戏或 GPU，不代表实际帧率。
- 每 120 次透明阶段回调输出一条 debug 汇总：列表准备、可见性分类和网格提交的平均/P95/最大 CPU 耗时、提交数、可见/驻留分区数，以及排序重建次数。提交计时不包含方块实体渲染、引擎其他阶段和 GPU 完成时间。
- 游戏内分别测试首次加载时转头、完全补齐后反复转头、持续移动转头；保留相同蓝图和画质。再覆盖旋转、镜像、切层、换蓝图、切维度、退出重进，检查缓存是否出现旧网格或遗漏。

## 群系染色与区块晚到

- 草类沿用原版细分时的染色面选择。`GrassTessellationPolicy::$get(Block const&, BlockSource&, BlockPos const&, BiomeTintCache const*) const` hook 仅在当前线程的投影虚拟世界作用域内，改用 `getMapPolicy(TintMethod::Grass).get(region, pos)` 采样；原版世界直接调用原函数并保留原缓存。不把泥土底面或雪覆盖面统一乘绿。此前向 TessellationPolicy 传空缓存的修改已撤回：头文件签名不能证明空缓存保证返回有效颜色。
- API 均核对实际依赖 LeviLamina 26.60.0 头文件。采样邻域取 `BiomeColorSampling::getPattern` 所有已声明模式的偏移并集，异步 ChunkView 和就绪检查使用同一范围，避免只保留原来的两格邻域。
- 构建时记录含草/树叶的网格是否早于 `BlockSource::areChunksFullyLoaded(min, max)`；结果与网格一起经过 worker generation、structure generation 和 revision 校验发布。不改变方块正确性也能触发一次染色重建，不依赖整张蓝图的纠错初扫完成。
- 每帧可见扫描、后台扫描各最多查看 128 条分区元数据；世界就绪查询分别最多 8 次、2 次。同一分区的未加载查询至少间隔 60 个不透明渲染帧，等待只检查依赖、不构建网格。就绪后清除待刷新标志、消耗一次自动补建额度、递增 revision，交给原有异步执行器。脏分区和构建中分区不会被旧依赖再次打断。
- 加载检查、采样值检查和全黑面是三个独立信号。草类采样若为全零 RGB、非有限值或超范围值，按投影显示策略暂用 `Biome::DEFAULT_GRASS_TINT()` 并记录被拒绝的样本；这不是引擎给出的“数据未就绪”标记。QuadList 输出全黑面也只记录为诊断现象，不能据此断言群系或光照未就绪。检测合并进已有的顶点颜色循环，不额外遍历顶点；单个暗角不触发判断，不重染泥土面。
- 每分区、每次外部内容版本最多自动补建 3 次，等待期限为 60/120/240 帧；仅全黑面而无其他异常时最多诊断补建 1 次。预算覆盖主线程加载检查与工作快照加载检查长期不一致的情况，不因一次颜色读取成功而补充。上传后按当前会话帧设置期限，结果沿用已消耗额度；达到上限后清除 pending，不再产生该分区的就绪查询或补建。实际纠错/邻居内容变化、用户设置失效或新摆放可重置额度，转头和时间经过不重置。debug 日志按受影响构建计数的 1/2/4/8… 次输出被拒绝样本、黑面、已用/总额度、pending 和等待期限，避免把现象直接写成原因。
- 待刷新数据只有坐标、标志和数值期限，归属 SectionState；游标和帧号归属 ProjectionState。采样失败标记在现有线程局部虚拟世界 RAII 作用域内收集并恢复。旋转/镜像/移动触发原有版本失效并清除旧采样依赖与退避，换维度/世界随会话释放；没有新增长期线程、世界引用或跨会话回调。
- 纯规则测试覆盖 16384 分区的预算上限、视野优先、未就绪不重建、就绪仅失效一次、脏/进行中任务和清空/缩容，以及全零/NaN/Inf/超范围样本、有效暗色保留、完整黑面与暗角区别。分别模拟样本持续异常、主线程/工作视图就绪状态不一致、持续全黑面各 10000 帧，断言实际补建次数及耗尽后零查询；还覆盖未加载查询节流、成功样本不补额度及外部重置。仍需游戏内检查跨群系草地、草/蕨类、雪面、树叶、区块加载边缘，并确认关闭/重开、移动、旋转与切维度后的显示；纯规则测试不能验证游戏实际顶点颜色，也不能证明黑块根因。

## 死代码与防御性编程审计

- 范围为 `b9b5a36` 之后的绘制缓存、群系刷新未提交修改，并复核相接的任务发布与生命周期调用链。
- 黑面批量检测包装函数只由测试使用，已移入测试文件；生产头文件只保留实际使用的流式顶点观察器。染色兜底只验证引擎默认色，移除对已被调用方拒绝的原样本再次判断的分支。
- 刷新期限统一由渲染线程在异步结果通过版本校验并发布时、或同步构建完成时设置；移除工作快照里的帧号复制和随后必然被覆盖的期限计算。刷新函数必须显式传入帧号，避免默认零让延迟任务永久等待。
- 内部补建计数通过断言表达上限约束，不再静默截断非法计数；派发边界仍保留额度耗尽检查，确保停止查询和补建。Blend 资源位仍与引擎桶保持一致，但不为其始终为空的列表预留堆内存，实际绘制使用透明地形列表。
- 任务结果先检查 worker/structure generation、分区范围、revision，再处理构建成功与否。过期失败只记为丢弃，不增加当前会话失败计数，不触发同步回退。此项为控制流审查与编译验证，未进行游戏内故障注入。
- 保留必要的引擎边界保护：无效矩阵保守绘制、材质存在性、GPU 网格 `isValid()`、发布版本校验和停止/等待工作线程后释放状态。诊断析构器的异常隔离只保护统计日志，不吞掉正常构建/提交的业务错误。缓存构建计数有回归测试与基准消费，不按死字段删除。
- 编译仍可见 LL hook 宏生成的 `_AutoHookCount` 未使用警告：该计数服务于框架的自动 HookRegistrar，本文件沿用显式 hook/unhook 安装与回滚。这不是染色业务里的遗留字段；未修改依赖头文件或用伪引用掩盖警告。
- 新增发布期限重置与 Blend 列表零预留检查；此前各 10000 帧的异常/预算测试继续保留。清理不改变草类采样策略、颜色回退策略或自动补建次数上限；游戏黑块根因仍未由这些逻辑测试证明。

## 异步加载的初始位置

- 普通加载按钮在启动文件线程前读取玩家当前位置，沿用原先的 `floor(x), floor(y)-1, floor(z)` 脚下锚点规则，同时记录点击时的维度编号。实际接口核对 LeviLamina 26.60.0 的 `ClientInstance::getLocalPlayer()`、`Actor::getPosition()`、`Actor::getDimensionId()`。后台线程只捕获数值请求，不捕获玩家/世界/维度对象。
- 初始位置属于 `StructureSession` 的运行时激活意图，不写入文件内容模型 `LoadedStructure`。加载成功后，结构和位置在同一会话锁内发布；渲染侧通过轻量快照读取，不额外复制结构数据。加载期间移动不会改变锚点；切维度后暂缓启用新文件，回到点击维度再启用。
- 最终审计移除只剩测试调用的通用 `replaceLoaded` 接口，测试装配复用实际恢复入口。所有有效结构发布都必须提供初始位置，启用阶段不再保留重新读取玩家当前位置的旧兜底。
- 每次普通文件请求携带会话 revision。关闭、世界会话清理、更新的文件请求或结构替换使旧请求失效，迟到的成功/失败不能覆盖当前结构、位置、变换或状态。加载失败保留旧投影的位置；新投影成功发布时才重置变换。
- 恢复保存投影时，保存锚点、变换和结构也统一在会话锁内发布，沿用原来的恢复维度策略。维度暂停/恢复继续优先使用暂停前的运行时锚点，避免回到原维度时退回最初点击位置。移除不再使用的全局“下一结构锚点”转发接口，内部锚点请求只负责维度恢复。
- 此项约束普通文件加载的结果发布，仍沿用现有 detached 文件线程；不声称解决解析器内部注册表访问与模组卸载的全部线程生命周期问题。
- `StructureLoadOriginTests` 覆盖点击位置值拷贝、等待中位置改变、失败保留旧位置、清理拒绝迟到结果、新请求胜出、保存位置恢复、旧快照不变和 64 次实际发布/清理并发竞态。游戏内需以大文件验证点击后移动、切维度、关闭投影及恢复保存投影。
