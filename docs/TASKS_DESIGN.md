# 建造任务与多文件投影

状态：已实现原生任务协议、持久化、文件合成和选中文件操作；等待游戏内验证。文件三维预览为独立用例，见 [文件结构预览](STRUCTURE_PREVIEW.md)。

## 现有边界

- `StructureSession` 仍发布一个不可变 `LoadedStructure`；任务合成器先处理多个文件，渲染、纠错和放置消费同一份获胜方块快照。快照带文件来源索引和真实覆盖区域。
- `config/config.json` v13 只保存用户偏好，旧单文件路径/锚点/恢复记录不再写入；历史配置保存在迁移备份中。任务是用户创建的数据，放在模组 `data/` 目录，不能将任务位置、目录或会话状态混入偏好配置。
- 正式任务、文件顺序、选中文件和保存状态由原生层拥有；`application/useTasks` 订阅快照并串行提交 revision/id 意图，页面只保留输入框草稿和弹窗状态。浏览器示例在 `preview/tasks.ts`，不进入正式包。

```text
  StructureFileLoader.*  共用异步任务门、Level 生命周期、原始文件缓存与完成结果
```

`tasks` 不依赖 OreUI、`app` 或 `projection`。`StructureTransform` 是共享纯坐标规则；`TaskComposer` 通过明确的方块状态变换回调复用 Bedrock 的旋转/镜像 API，不依赖投影模块。`app` 串联各模块，任务业务没有塞进 `MenuBindings`。运行态直接由已有职责模块拥有，不额外建立转发用的 TaskSession 包装层。

## 每文件整体边框

每个可见且已加载的投影文件拥有一个按完整文件尺寸计算的边框。旋转交换 X/Z 尺寸，镜像不改变完整外包围盒尺寸，XYZ 位移与合成归一化共同作用于边框位置；重叠、切片、选择其他文件都不裁剪或合并边框。隐藏文件不生成边框。多区域 Litematic 以整个文件的尺寸生成一个外框，区域间空隙仍属于同一个文件外框。

`LoadedStructure::sourceBounds` 独立记录这些显示范围，不扩大 `regions` 的纠错空气覆盖，也不写入任务数据。边框绘制复用 `render/BoxWireframeMesh` 的多盒批量接口，所有文件线框缓存成一次 GPU 绘制，每文件 24 顶点；不逐帧扫描方块或逐文件提交 GPU 绘制。现有总开关保持有效。回归覆盖重叠、隐藏、完整尺寸、切片、负位移、旋转/镜像、归一化、多区域空结构和全部隐藏。

## 持久化模型

文件位置：`mods/LHolo/data/tasks.json`。代码通过 `LHolo::getInstance().getSelf().getDataDir() / "tasks.json"` 获取路径，不自行拼接游戏安装目录。LeviLamina 的 `getDataDir()` 对应模组的 `data/`，`getConfigDir()` 对应 `config/`。`config/config.json` v13 只存全局偏好，不再保存旧单文件恢复记录。任务文件存储定义，不复制或导入投影文件；目录和文件在第一次保存任务时创建。JSON 字符串使用 UTF-8；路径使用用户选定的绝对路径，并复用 `StructurePaths` 做 Windows 路径转换。任务和文件 ID 在创建时生成，顺序由数组位置表示，不另存易失同步的编号或 ID 计数器。

```text
mods/LHolo/
  config/config.json       语言、HUD、快捷键等全局偏好
  data/tasks.json          用户创建的任务、外部文件引用、每文件维度/坐标和设置
  resource_packs/LHoloUI/  模组页面资源；不存用户数据
```

```json
          "position": { "x": 20, "y": 80, "z": 30 },
          "rotation": 0,
          "mirror": "none",
          "slice": { "axis": "y", "mode": "all", "index": 0 }
        }
      ]
    }
  ]

```

- 任务名称是用户输入的任意语言文本；显示文件名从路径派生，不重复存一份名称。缺失文件仍保留路径、ID 和全部设置。
- ID 是创建时生成的内部 UUID，仅用于重命名、改路径或调整顺序后仍能指向同一个任务或文件；用户看到的 1、2、3 始终由文件数组顺序计算。无需在 JSON 中保存 `nextTaskId` 或 `nextFileId`。
- `rotation` 直接保存顺时针旋转角度：`0`、`90`、`180`、`270`；运行时转换为现有结构变换使用的旋转枚举。
- `mirror` 直接保存 `"none"`、`"x"` 或 `"z"`：分别表示不镜像、沿 X 方向翻转、沿 Z 方向翻转；运行时映射到现有结构变换使用的镜像枚举。
- `selectedTaskId`、每任务 `selectedFileId` 是可恢复的选择偏好。`activeTaskId`、解析缓存、错误状态和世界/维度对象只属于运行态，不写入文件，也不在进入世界时自动激活任务。
- `dimension` 与 `position` 属于文件，保存绝对世界坐标，不保存任务锚点、世界 ID 或服务器地址。同任务可包含不同维度的文件，同一任务换存档或服务器也使用相同维度及坐标。新文件取首次成功加载时玩家的脚部方块坐标；未绑定文件使用 `dimension: null`。只读取当前 v2 格式，不兼容或迁移旧任务数据。
- 旧 `config.json` 和单文件恢复字段保持原义。任务模式发布合成结构时，`StructureSession` 必须明确记录来源类型，旧 `saveSettings()` 不得用合成结构改写单文件恢复快照。
- 保存只在原生层接受创建、删除、重排、显隐、变换、路径、选择更改或首次成功放置后触发。路径输入在前端编辑草稿，确认或失焦时提交一次；不逐字符重载和写盘。控制帧将最新目录交给独立写入线程，连续修改在停止编辑 300 ms 后合并写入；已有写入不并发重入，停用时等待最后一份目录落盘。写入错误返回任务状态，不使用同步写入兜底。任务变换、切片和合成锚点不再触发旧全局配置保存，视觉样式等全局设置仍保存到配置。
- 写盘先在同目录写完整临时文件，再原子替换目标文件；这不是长期备份。启动时校验版本、ID 唯一性和字段范围。解析失败时报告错误并保留原文件，不用空任务列表覆盖它。
- `mods/LHolo/data/tasks.json` 已列入 `tooth.json` 的 `preserve_files`；安装包只含程序和页面资源，不带用户任务数据。`tools/oreui/deploy.ps1` 仅复制固定的六个安装文件，不删除 `data/`。

## 激活与合成

2026-10-28 增加简单的独立文件分支：对旋转后的完整文件 AABB 逐对检测，不遍历方块；任一轴有至少一格空隙即可分离，镜像不改变外部尺寸。所有可见文件互不重叠且不紧贴时，`IndependentTaskFiles` 仅保存原始文件及其变换，每个文件直接走原单文件渲染/纠错流程。移动选中文件在当前渲染帧读取实时参数，仍保持独立时不等待异步任务结果；未变化文件的运行状态不随任务 generation 更换。重叠或紧贴时走下面的原合成规则；三个及以上文件中只要有一对相互影响，当前版本整个任务仍回到原合成管线，不引入依赖图或分组交接。独立文件直接使用原完整边框，保留原分层、材料和放置查询规则。

`IndependentFileProjection` 仅负责文件实例复用与公共队列路由；相关方块/子区块事件分发一次，Worker 结果按文件实例 generation 分发，单文件失效/revision 校验不变。同路径重复附加共用原始数据，但运行态身份独立。没有防抖、16 格邻接扩张、轮转更新或等待全量纠错后再移动的门槛。每文件继续使用原单文件每帧预算，多文件首次扫描的总工作量会增长；世界/维度释放仍由根先停止 Worker 再释放文件状态。切换独立/合成模式会按原管线重新激活，该边界的重建体验仍需实机验证。

`IndependentTaskFilesTests` 覆盖 XYZ 分离、紧贴、重叠、90/180 度旋转、镜像、负偏移、重复路径、隐藏与全部隐藏、实时移动可否保持独立、溢出拒绝，并确认独立分支不调用方块合成变换、A 移动保留 B 原始指针及偏移；`TaskActionsTests` 使用新的选择分支验证任务锚点、关闭重开和失败恢复。用户于 2026-10-28 反馈本版实机测试通过；原生网格保留、移动延迟、跨文件红石模型和帧耗时继续纳入后续游戏内回归。

这里的“文件层”指任务中按 1、2、3 排列的投影文件；“切片层”指单个文件内部按 X/Y/材料筛选的显示层。两者不能共用一个显隐字段。文件层的 `visible` 是任务合成的输入，直接决定该文件的蓝图方块能否出现在世界中；切片只进一步筛选这个文件贡献的方块。

同一任务坐标的有效方块 = 顺序最靠前、已开启、未被切片隐藏且该处不是空气的文件方块；找不到则为空。渲染、纠错、HUD 和辅助放置都以这个有效结果为准，不允许各自重新解释文件层开关。

1. 每文件使用保存的维度和绝对 XYZ。加载前仅将用户开启且维度等于玩家当前维度的文件传为可见输入；其他维度不加载缺失文件、不参加 AABB/纠错/材料/放置，也不修改用户的显隐偏好。新文件只在待加载副本中绑定当前维度和脚部坐标，成功后按文件 ID 提交。退出世界仅释放运行态；重进后已绑定文件使用保存值。维度切换自动重建当前任务的维度视图，选中其他维度的文件不接受编辑；失败不反复自动重试，每次新的维度切换或显式加载可再尝试。主世界/下界坐标不自动转换。
2. 加载与合成使用一次任务 revision。解析任务期间如切换任务、修改路径或退出世界，旧结果不得发布；世界销毁前等待仍使用该世界方块注册表的解析任务结束，沿用现有文件加载器的生命周期约束。
3. 每个文件先以自身尺寸执行旋转/镜像，再加该文件保存的绝对 XYZ；方块朝向也按现有 Bedrock 变换规则转换。只在当前维度内判定重叠，切片过滤先于获胜判定；第一个可见的非空气方块（含液体和方块实体）获胜，高优先级空气不遮挡下方文件。只保留获胜者参与纠错、材料和放置。合成坐标仍可归一化，但归一化原点只用于渲染，不写回文件位置。
4. 合成结果仍提供现有投影需要的、按本地 XYZ 排序的 `LoadedStructure::renderBlocks`，并重算材料索引、尺寸和 generation；另保留获胜方块到文件 ID 的来源索引。不能简单把多个文件的 `renderBlocks` 拼接：当前纠错按坐标二分查找，材料层依赖索引，额外方块检测依赖来源区域。
5. 合成区域需保留每个文件变换后的有效覆盖范围，并正确处理重叠与空洞；不能把整个合成包围盒都当成结构空气，否则文件之间的空白区域会被错误地统计为“多余方块”。
6. 所有可见文件加载并合成成功后一次性发布新的不可变快照。失败时保留旧的运行投影，向任务页返回具体文件 ID 和错误；修改路径后可重试。移动/显隐/排序/切片使用原始文件缓存，只重合成；显式激活时重新读取外部文件，检查文件移动或内容变更。同一路径重复附加时一次解析、多份独立变换。

运行态分别持有上次成功的文件定义和正在合成的定义；失败不覆盖成功定义，也不删除目录中待修复的路径。失败后选中旧投影已有的文件时，从成功定义绑定编辑器；快捷键以该定义重合成，并仅按文件 ID 将变换同步回任务目录。新附加但未成功加载的文件没有旧编辑目标，不能误操作前一个文件。显式加载或目录修改仍使用最新目录，不跳过报错文件。

### 文件层显隐的运行规则

- `visible = false` 的文件完全退出有效投影：不绘制蓝图方块、不参与重叠抢占、不贡献纠错和材料统计，也不提供任何辅助放置候选。选中状态和文件设置仍保留，用户可继续编辑或重新开启。
- 隐藏高优先级文件后，原来被它遮住的低优先级方块会显示；重新开启则按顺序重新决定获胜文件。文件层顺序或切片变化也按同一规则重合成。
- 显隐操作不是只更新 UI。合成结构、虚拟方块查询、渲染网格、纠错快照、HUD/材料统计及放置候选必须使用同一代有效投影；旧异步网格结果不得在新显隐状态下发布。
- 所有文件隐藏时任务仍可保持选中及激活，但有效投影为空：世界中无蓝图方块，HUD 显示“无可见投影文件”，纠错和放置查询均为空。当前投影初始化拒绝空 `renderBlocks`，实现时须为这种状态提供明确的空投影路径。

## 生命周期与页面

- 任务目录在 `AppKernel::load()` 读取，原生接受的数据变更立即保存。退出世界清理激活态、编辑目标和世界文件缓存，任务定义继续存在；维度切换重新发布当前维度的文件视图，其他维度文件保持原有维度及坐标。退出后重进或换服务器须显式加载任务，并沿用相同的文件维度和坐标。
- 任务页快照包含 task/file ID、顺序、选中、显隐、路径、加载状态及 revision；意图按 ID 提交，不能用数组索引做永久身份。前端重排后必须以原生返回快照为准。
- 现行菜单只保留任务入口，默认打开建造任务；旧单文件页及专用浏览/加载/恢复通路已移除。文件操作依据激活任务的选中文件，结构变换页明确显示操作目标，并通过绑定目标的 context 校验。切片属于文件级数据，整体纠错样式仍是全局设置。材料清单位于任务页，显示当前选中文件的名称和统计。
- 文件预览通过独立只读解析通道和原生场景提供，不改变任务选择或激活投影；当前依赖游戏世界的方块注册表，标题画面禁用入口。详见 STRUCTURE_PREVIEW.md。

## 操作目标

`selectedTaskId` 是任务页当前选择，`selectedFileId` 是该任务中的当前文件；`activeTaskId` 是世界中加载成功的任务运行态。世界中选择或新建任务后自动加载并合成，成功才切换运行目标；失败时保留原投影。“加载任务”也可显式重新加载当前任务；标题界面只管理数据，进入世界不自动激活上次任务。切换激活任务中的选中文件只改变编辑/查询目标，不重建网格。查询同时校验当前合成快照的身份，排序发布交接时不把旧索引套到新快照。结构变换和渲染页显示当前操作文件。

| 功能 | 作用对象 |
| --- | --- |
| 文件移动、旋转、镜像、切片快捷键和结构变换页 | 当前激活任务的选中文件；修改后重合成任务投影 |
| 投影 HUD 的文件名、层信息、建造进度、错误数、材料 HUD | 当前激活任务的选中文件；只统计该文件在合成结果中最终获胜且可见的方块 |
| 轻松放置、手动放置、范围放置 | 当前激活任务的选中文件；只能命中该文件最终获胜且缺失的方块 |
| 任务切换、激活和关闭投影 | 整个任务；菜单快捷键与 HUD 布局/显隐偏好仍是全局设置 |

投影查询及范围候选需要携带获胜文件 ID，并在原生查询层按 `selectedFileId` 筛选；不能只在前端隐藏结果。隐藏或缺失的选中文件没有可放置候选。重叠位置的正确/错误状态归获胜文件；没有预期方块的“多余方块”须按覆盖范围确定唯一所属文件，避免 HUD 双重计数。任务级总进度若以后需要，应作为单独指标提供，不混入选中文件 HUD。

## 替换路径与分层校正

“修改路径”替换条目引用的文件，保留条目的绝对锚点、维度、旋转、镜像和分层模式，不计算文件哈希来推断意图。所有需要的文件成功解析后、进入独立投影或重叠合成前，由 TaskComposer 的 normalizeCompositionLayers 按各源文件的当前分层轴限制层号：Y 使用 sizeY-1，X 使用 sizeX-1，材料使用 materialCount-1，下限及空材料上限均为 0。有效层号不变，隐藏且未读取的文件等取得真实尺寸后再校正。

StructureFileLoader 在结果中携带实际参与合成的校正值；TaskActions 只在 revision、请求及合成发布均成功后，将这些值同步给当前任务定义、编辑会话和 tasks.json。加载失败或结果过期不应用校正，不改变原有效投影。界面通过现有原生快照读取，不新增前端补偿或每帧校验。

## 独立文件的网格完成与调度

所有文件共用 Worker 的一个完成队列。根投影在 opaque 帧按原有两项/1 ms 预算逐个取出结果，以 Worker generation 和运行实例 generation 直接路由到对应文件，再校验 section revision；不设文件级中转队列，未消费结果继续留在全局队列，已移除文件的结果直接丢弃。避免批量清空中转队列后只上传首项，导致其余分区永久停在 in-flight 状态。

所有文件仍在每个 opaque 帧处理纠错、实时变换与绘制，仅轮换第一个访问者，让后续文件有机会提交到唯一 Worker；transparent 绘制顺序不变。此处轮换不跳过文件、不等待网格完成才应用变换，不增加另一套渲染路径。

## 验证

`TaskTests` 覆盖重叠优先级、空气透出、隐藏、切片、负偏移、旋转后尺寸、文件间空洞、全部隐藏、来源身份、UTF-8 持久化、排序和稳定 ID、删除最后任务、重复 ID 拒绝、任务协议、旧恢复记录隔离及退出世界拒绝迟到结果，并验证异步保存最终目录和写盘错误。`TaskActionsTests` 替换游戏/文件读取边界，运行真实控制帧、会话、合成和保存，覆盖失败后继续编辑、路径修复、关闭和退出世界的迟到结果；另验证走开后关闭重载和重启后的绝对坐标不变、同任务主世界/下界/末地筛选、相同 XYZ 在不同维度不重叠、首次放置失败不提交，以及加载器忙时移动并切维度后重试捕获新的位置与维度。退出世界仍清理运行态，换世界后按用户要求沿用相同坐标。前端隔离测试验证任务页只发送意图、等待原生快照、输入法候选确认不提交和超长请求拒绝后仍可操作。

仍需游戏内验证两个真实文件的重叠/显隐/移动/旋转/切片、跨文件邻接和方块实体、选中文件放置与 HUD、缺失路径修复、重启恢复任务目录，以及加载期间退出世界和切维度。独立原生文件预览也需实机验证。
